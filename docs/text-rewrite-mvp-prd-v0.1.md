## 1. 产品结论

### 1.1 一句话定义

用户在任意应用中选中文字，按下全局快捷键，即可在光标附近唤起一个轻量菜单，选择“改写、友好、专业、简洁、校对或自定义指令”，在预览结果后一键替换原文或复制结果。

### 1.2 最重要的产品判断

“任意输入框都可唤起菜单”不应在 MVP 中理解为“把按钮注入每一个 App 的输入框”。Windows 第三方应用无法稳定地向所有原生和第三方应用注入统一右键菜单。

推荐采用以下路径：

- **MVP：全局快捷键 + 光标附近浮层菜单 + 选区读取 + 一键替换**
- **增强版：浏览器扩展**，为网页输入框提供悬浮按钮和右键菜单
- **远期：与具体产品合作/提供 SDK**，在目标编辑器内嵌更原生的入口

这样既能覆盖用户真实场景，又能控制兼容性、权限和研发风险。

### 1.3 核心价值

1. **不打断工作流**：不要求复制到另一个网页、编辑器或聊天窗口。
2. **零提示词门槛**：高频改写意图已经做成菜单项。
3. **结果可控**：先预览后替换，随时恢复原文。
4. **跨应用一致**：邮件、浏览器、Office、IM、CRM 中使用同一套操作。
5. **可控的自定义能力**：预设覆盖不了时，用一句话描述修改要求。

## 2. 背景与对标

### 2.1 iOS 18 Writing Tools 的关键事实

iOS 18 的 Writing Tools 可在大多数写作场景中唤起，支持：

- 校对；
- 改写；
- 友好、专业、简洁三种语气；
- 用自然语言“描述你的修改”；
- 总结、要点、列表、表格；
- 结果预览、原文/结果切换、重试、恢复原文；
- 复制、替换、分享。

它默认处理“选中的文本”，而不是自动读取整个文档；改写结果先预览，用户主动确认后才替换。该闭环非常值得复用。

### 2.2 我们借鉴什么

- 系统级、贴近编辑现场的入口；
- 高频意图预设，不要求用户写提示词；
- 默认非破坏性，结果可预览、可回退；
- 原文和结果可来回切换；
- 自定义指令作为兜底能力；
- 只处理用户明确选中的内容。

### 2.3 我们暂不照搬什么

- 不追求在 MVP 阶段覆盖所有应用的右键菜单；
- 不在 MVP 中自动读取整篇文档或输入框上下文；
- 不在 MVP 中提供总结、列表、表格、从零撰写；
- 不监听用户日常输入内容。

## 3. 用户与场景

### 3.1 目标用户

| 用户类型 | 主要痛点 | 典型场景 |
|---|---|---|
| 职场沟通用户 | 邮件、IM 消息不够得体或表达拖沓 | 改写客户回复、周报、会议纪要 |
| 销售/客服 | 需要快速切换友好、专业语气 | 跟进消息、问题回复、异议处理 |
| 内容创作者 | 重复调整语气、压缩文案 | 公众号、小红书、短视频脚本 |
| 学生/求职者 | 表达不清晰、英文或书面语不自然 | 论文段落、简历、申请邮件 |
| 跨语言工作者 | 需要保持原意并改善表达 | 中英邮件、海外客户沟通 |

### 3.2 核心用户任务（JTBD）

- 当我正在写一段文字时，我想快速改得更通顺，而不用打开另一个 AI 页面。
- 当我不确定语气是否合适时，我想一键切换为更友好或更专业。
- 当内容太长时，我想在不丢失重点的前提下压缩。
- 当文字有语病时，我想只修错、不改变我的表达风格。
- 当预设都不满足时，我想用一句话描述修改要求并立即看到结果。

### 3.3 典型使用场景

1. 在 Outlook 写邮件，选中正文，按快捷键改成“更专业”。
2. 在微信/企业微信写客户回复，选中文字，按快捷键改成“更友好”。
3. 在浏览器里的 CRM 输入框写跟进记录，压缩成“更简洁”。
4. 在 Word 中校对一段草稿，查看修改并选择是否替换。
5. 在任意只读页面选中一段文字，改写成更清晰的表达后复制。

## 4. 产品目标与非目标

### 4.1 产品目标

- 用户从选中文本到看到改写结果，不超过 3 个明确动作。
- 让用户在 10 秒内完成一次常规短文本改写（不含模型极端延迟）。
- 支持 Windows 主流应用中的标准可编辑文本控件。
- 任何失败路径都不能导致原文丢失。
- 用户能清楚知道哪些内容会被发送到 AI 服务，并能关闭或清除本地记录。

### 4.2 MVP 非目标

- 不做完整写作编辑器；
- 不做自动监听键盘、自动改写或自动发送；
- 不做整篇文档一键重写；
- 不做多人协作、团队知识库、审批流；
- 不做移动端；
- 不做浏览器扩展（列为下一阶段）；
- 不做离线模型（列为后续方案）；
- 不承诺覆盖游戏、终端、远程桌面、密码框、提权应用。

## 5. 范围与优先级

| 优先级 | 能力 |
|---|---|
| P0 / MVP | Windows 全局快捷键唤起；读取选中文本；浮层菜单；改写/友好/专业/简洁/校对/自定义；结果预览；复制；替换；撤销替换；快捷键设置；基础错误处理；隐私说明 |
| P1 | 改写结果差异高亮；摘要/要点；从零撰写；本地历史；自定义预设；浏览器扩展；选中内容语言识别与目标语言设置；富文本格式保留 |
| P2 | 读取当前文档上下文；团队模板；企业私有化模型；Mac 端；移动端；SDK/嵌入式入口 |

### 5.1 MVP 建议菜单

第一层菜单建议保持 6 个高频入口：

1. 智能改写
2. 更友好
3. 更专业
4. 更简洁
5. 校对优化
6. 自定义指令

说明：

- “智能改写”是默认项，悬停或键盘回车直接执行。
- “校对优化”只修语法、错别字和明显表达问题，不做风格重写。
- “自定义指令”打开单行输入框，用户可输入“更口语”“压缩到 100 字以内”“保留 Markdown 结构”等要求。
- 总结、要点、列表、表格、从零撰写放到 P1，避免首屏过重。

## 6. 核心用户流程

```text
用户在任意应用中选中文字
        ↓
按下 Ctrl+Alt+R（默认，可配置）
        ↓
工具读取选区，在光标附近弹出快捷菜单
        ↓
用户选择改写意图
        ↓
显示生成中状态，可取消
        ↓
展示结果预览：原文 / 结果切换
        ↓
重新生成 / 复制 / 替换 / 关闭
        ↓
替换成功后可撤销；失败则保留结果供复制
```

### 6.1 成功路径

1. 用户在 Chrome 的输入框中选中一段文字。
2. 按下全局快捷键。
3. 菜单在选区附近出现，并显示“已选中 126 字”。
4. 用户点击“更专业”。
5. 结果卡片在 1～5 秒内出现。
6. 用户切换到“原文”对比后，点击“替换”。
7. 工具把结果粘贴回原输入框，并显示“已替换，撤销”提示。
8. 用户点击“撤销”可恢复原文。

### 6.2 取消路径

- 按 Esc、点击浮层外部或点击关闭：关闭菜单，不修改原文。
- 生成过程中取消：中止请求，不写入剪贴板。
- 替换前关闭：原文保持不变。

## 7. 功能需求

### FR-01 全局唤起

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 描述 | 应用常驻托盘，用户按下可配置的全局快捷键后唤起菜单 |
| 默认快捷键 | `Ctrl+Alt+R`，设置页可修改 |
| 触发条件 | 用户已明确选中文本 |
| 无选区时 | 显示轻提示“请先选中要改写的文字”，不弹出生成菜单，不读取剪贴板文本 |
| 冲突处理 | 注册快捷键失败时提示冲突，并引导用户修改 |
| 单实例 | 同一时间只允许一个改写浮层存在 |

**验收标准**

- 在记事本、Chrome、Word 中选中文字后，快捷键可稳定唤起菜单。
- 未选中文字时按快捷键，不会把剪贴板中的旧文本误当作选区。
- 快捷键冲突时应用不崩溃，并提示用户更换。

### FR-02 选区读取

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 主方案 | 优先通过 Windows UI Automation 的文本选择能力读取 |
| 兜底方案 | 用户触发后模拟复制，读取剪贴板新增内容 |
| 安全限制 | 不读取密码框、安全输入控件和无法确认类型的敏感字段 |
| 长度限制 | MVP 单次最多 5,000 个中文字符或等价文本量，超限明确提示 |
| 剪贴板处理 | 读取后恢复用户原剪贴板；不持续监听剪贴板变化 |
| 明确授权 | 只有用户按下快捷键后才读取选区，不做后台扫描 |

**验收标准**

- 在标准 Win32 文本框、Chrome 输入框、Word 正文中可读取选区。
- 读取失败时有明确提示，不进入模型调用。
- 复制兜底不会泄露或覆盖用户原有剪贴板内容。
- 密码输入框和明确标记为安全输入的控件不展示改写菜单。

### FR-03 浮层菜单

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 位置 | 靠近鼠标/选区，自动避让屏幕边缘，支持多显示器和高 DPI |
| 首屏内容 | 6 个 MVP 改写意图 |
| 键盘操作 | 方向键切换、Enter 执行、Esc 关闭 |
| 状态提示 | 显示选中的字符数量 |
| 关闭行为 | 点击外部、Esc、关闭按钮均可关闭 |
| 视觉 | 跟随系统深/浅色；不使用会遮挡原文的大尺寸面板 |

**验收标准**

- 菜单不超出当前显示器边界。
- 125%、150%、200% 缩放下位置和点击区域正确。
- 键盘可完成“唤起 → 选择 → 执行 → 关闭”全流程。

### FR-04 改写意图

| 优先级 | 菜单项 | 行为定义 |
|---|---|---|
| P0 | 智能改写 | 改善通顺度、清晰度和表达质量，尽量保持原意和长度 |
| P0 | 更友好 | 语气更亲切、有温度，但不过度热情或谄媚 |
| P0 | 更专业 | 更正式、清晰、可信，避免生硬术语堆砌 |
| P0 | 更简洁 | 删除冗余，保留事实、数字和关键结论 |
| P0 | 校对优化 | 只修正错别字、语法、标点和明显病句，保留个人风格 |
| P0 | 自定义指令 | 按用户自然语言要求改写，同时遵守事实保真和输出格式约束 |

#### 各模式的输出约束

- 默认输出语言与输入语言一致。
- 保留原文中的姓名、数字、日期、金额、链接、引用和专有名词。
- 不主动添加原文没有的事实、结论或承诺。
- 保留原有段落、列表和换行结构；输入不是 Markdown 时不主动输出 Markdown。
- 只返回改写后的正文，不输出“改写如下”“以下是修改版本”等解释。
- “智能改写”长度控制在原文的 80%～120% 左右。
- “更简洁”不设固定压缩比例，但不能删除关键条件、数字和结论。
- “校对优化”长度变化不超过 10%，除非原文存在明显重复。

### FR-05 自定义指令

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 输入长度 | 最多 200 个字符 |
| 提交方式 | Enter 提交，Shift+Enter 换行 |
| 空内容 | 不允许提交，并提示输入修改要求 |
| 快捷建议 | 提供“更口语”“更正式”“压缩到 100 字内”“保留专业术语”等可点击示例 |
| 安全约束 | 自定义指令不能覆盖事实保真、禁止添加事实、只输出正文等基础规则 |

**验收标准**

- 输入“改成更口语，保留所有数字”后，结果符合要求且数字不丢失。
- 输入“只说结论，不要解释”时，结果不出现额外的提示语。

### FR-06 AI 处理与生成中状态

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 请求内容 | 仅包含选中文本、改写模式、自定义指令和必要的语言/格式参数 |
| 生成状态 | 300ms 内出现“正在改写”状态；提供取消按钮 |
| 流式输出 | 建议支持；没有流式能力时至少显示进度状态 |
| 超时 | 20 秒超时并进入可重试错误态 |
| 重试 | 支持重新生成，保留原文 |
| 并发 | 同一用户默认只允许一个改写请求，避免重复点击 |
| 服务端密钥 | AI 密钥不得下发到客户端 |

**性能目标**

- 500 字以内文本：P50 首屏可见 ≤ 2 秒，P50 完整结果 ≤ 5 秒，P90 ≤ 8 秒。
- 5,000 字文本：允许更长时间，但必须显示进度并可取消。
- 实际 SLA 需在选定模型服务和部署区域后重新确认。

### FR-07 结果预览

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 视图 | 提供“结果 / 原文”切换 |
| 结果操作 | 重新生成、复制、替换、关闭 |
| 替换可用性 | 目标文本可编辑时可用；只读文本时禁用 |
| 预览前 | 不修改目标应用中的原文 |
| 结果为空 | 视为失败，允许重试，不自动替换 |
| 结果与原文相同 | 提示“未产生明显变化”，仍允许复制或重试 |
| 文本长度 | 结果卡片可滚动，不因长文本撑出屏幕 |

**验收标准**

- 用户可在替换前完整查看结果。
- 切换到原文不会丢失生成结果。
- 只读场景下只显示复制，不显示可点击的替换按钮。

### FR-08 替换原文

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 机制 | 将结果写入剪贴板，恢复目标窗口焦点，模拟粘贴 |
| 前提 | 原目标控件仍在、焦点可恢复、控件仍处于可编辑状态 |
| 失败处理 | 替换失败时保留结果，提示用户手动复制，不重复尝试破坏性写入 |
| 富文本 | MVP 按纯文本粘贴；格式保留列为 P1 |
| 校验 | 尽量通过 UI Automation 校验文本是否变化；无法校验时提示“如未生效请使用复制” |

**验收标准**

- 在记事本、Chrome、Word 中，替换后文本正确出现在原位置。
- 目标窗口被关闭或切换应用时，不向错误窗口粘贴。
- 替换失败不会清空原文。

### FR-09 撤销替换

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 触发 | 替换成功后显示 10 秒“撤销”提示 |
| 行为 | 将替换前原文重新写回原控件 |
| 前提 | 目标应用和控件仍可用 |
| 失败处理 | 提示用户原文已保存在本次会话中，可复制恢复 |
| 记录 | 默认仅在内存中保留本次替换信息；持久历史为 P1 |

**验收标准**

- 替换后立即点击撤销，原文恢复。
- 关闭应用后，临时替换信息被清除。

### FR-10 设置

| 项目 | 要求 |
|---|---|
| 优先级 | P0 |
| 全局快捷键 | 可修改、可检测冲突、可恢复默认值 |
| 菜单配置 | MVP 支持调整菜单项顺序和隐藏低频项；自定义预设为 P1 |
| 启动项 | 用户可设置是否开机启动，默认关闭 |
| 主题 | 跟随系统，可手动切换浅色/深色 |
| 隐私 | 提供隐私说明、清空本次会话数据、关闭历史记录 |
| 关于 | 版本号、服务条款、隐私政策、问题反馈入口 |

### FR-11 历史记录（P1）

- 默认关闭持久化历史。
- 开启后仅保存在本机，默认保留 7 天。
- 记录内容包含：时间、模式、原文、结果、目标应用名称。
- 支持按时间清理、单条删除和全部清空。
- 不记录密码、安全字段、剪贴板中的非本次选区内容。

### FR-12 总结与结构化（P1）

- 总结、要点、列表、表格作为独立分组。
- 结果支持复制和替换；只读源文本不显示替换。
- 表格输出需遵循目标输入场景，纯文本场景中默认使用可读的 Markdown 表格或制表符结构，具体规则待确认。

### FR-13 从零撰写（P1）

- 无选区时允许进入“撰写新内容”。
- 用户输入写作要求，并选择是否带入当前选中文本。
- 生成结果只读预览，确认后可复制或粘贴到当前可编辑控件。
- MVP 不做该能力，避免“无选区”流程与改写主流程混淆。

## 8. 界面与交互建议

### 8.1 快捷菜单

```text
┌────────────────────────────┐
│  已选中 126 字              │
│                            │
│  ✦ 智能改写                 │
│  ☺ 更友好                   │
│  ◇ 更专业                   │
│  ↕ 更简洁                   │
│  ✓ 校对优化                 │
│  ✎ 自定义指令…              │
│                            │
│  Esc 关闭   Enter 执行       │
└────────────────────────────┘
```

### 8.2 结果卡片

```text
┌──────────────────────────────────────┐
│  改写结果                    ×        │
│  [结果] [原文]       已生成 238 字     │
│                                      │
│  这里是改写后的正文……                  │
│                                      │
│  [重新生成]  [复制]  [确认改写]        │
└──────────────────────────────────────┘
```

### 8.3 交互原则

- 不打开独立网页，不打断当前任务。
- 首屏不做参数堆叠，不要求用户选择模型。
- 结果和原文必须可来回切换。
- 替换是明确的主动动作，不能自动执行。
- 所有主要操作支持键盘完成。
- 错误提示必须说明“发生了什么”和“下一步怎么做”。

## 9. 技术实现建议

### 9.1 推荐架构

```text
系统托盘 / 设置页
        │
全局快捷键（RegisterHotKey）
        │
选区读取（UI Automation 优先 + 剪贴板兜底）
        │
浮层菜单与结果卡片
        │
AI 服务（服务端代理，客户端不保存密钥）
        │
写回（剪贴板 + 模拟粘贴 + 焦点校验）
```

### 9.2 平台兼容分级

| 级别 | 场景 | MVP 预期 |
|---|---|---|
| A | 记事本、标准 Win32 文本框、Chrome 普通输入框、Word 正文 | 完整支持 |
| B | Electron 应用、部分自定义编辑器 | 剪贴板兜底，替换多数可用 |
| C | 富文本、表格、代码块、邮件签名区 | 尽力支持，格式可能丢失 |
| D | 密码框、终端、游戏、远程桌面、提权应用、受保护输入 | 不支持或明确警告 |

### 9.3 关键风险

- 通过模拟复制读取选区会短暂占用剪贴板，剪贴板管理器和安全软件可能产生提示。
- 某些应用会拦截 Ctrl+C、Ctrl+V 或焦点恢复，需提供兼容性反馈。
- 全局快捷键可能与其他软件冲突。
- 替换属于跨应用写入操作，必须严格确认目标窗口和控件，避免粘贴到错误位置。
- 若产品只面向 Web，浏览器扩展比桌面全局方案更可靠，应重新评估入口设计。

## 10. 非功能需求

### 10.1 性能

- 冷启动后托盘可用时间 ≤ 3 秒。
- 快捷键唤起菜单 P95 ≤ 200ms。
- 500 字以内文本改写 P50 完整返回 ≤ 5 秒，P90 ≤ 8 秒。
- UI 不得因模型请求阻塞；生成中可取消。

### 10.2 稳定性

- 支持应用崩溃后重启，不丢失用户原文（临时会话数据除外）。
- 单次失败不影响下一次改写。
- 主流场景替换成功率目标 ≥ 95%。
- 崩溃自由会话率目标 ≥ 99.8%。

### 10.3 隐私与安全

- 不监听日常键盘输入，不做后台全文扫描。
- 仅在用户主动触发且存在选区时读取文本。
- 不读取密码框、安全输入控件。
- 默认不持久保存原文和改写结果。
- 本地历史如启用，必须明确告知并提供一键清除。
- 传输使用 TLS；AI 密钥保存在服务端。
- 不将原文用于模型训练，若使用第三方服务需在隐私政策中明确说明数据流向和保留策略。
- 不把用户文本写入日志；错误日志只记录长度、耗时、错误码等元数据。

### 10.4 可访问性

- 菜单支持键盘导航和屏幕阅读器朗读。
- 支持 125%～200% 系统缩放。
- 支持高对比度主题和深色模式。
- 焦点状态、选中状态和禁用状态可辨识。

### 10.5 国际化

- MVP 支持中文和英文界面。
- 默认自动识别输入语言并保持同语言输出。
- P1 支持指定目标语言。
- 日期、数字、金额和链接在改写后应保持原样。

## 11. 指标与埋点

### 11.1 北极星指标建议

**每周成功完成并替换的改写次数**。

它比“唤起次数”更接近真实价值，能排除无效点击和失败体验。

### 11.2 关键指标

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| 唤起成功率 | 快捷键成功打开菜单的比例 | ≥ 99% |
| 选区读取成功率 | 成功读取有效选区的比例 | ≥ 95% |
| 改写完成率 | 打开菜单后成功得到结果的比例 | ≥ 90% |
| 替换采用率 | 得到结果后选择替换的比例 | 观察值，首版不低于 40% |
| 撤销率 | 替换后又撤销的比例 | 用于评估模型质量，目标 < 10% |
| 失败率 | 网络/模型/写入失败占比 | < 5% |
| P90 延迟 | 500 字文本完整返回时间 | ≤ 8 秒 |
| 留存 | 7 日内再次使用比例 | 内测阶段观察 |

埋点不得上传原文、改写结果或剪贴板内容，只记录事件类型、模式、字符数区间、耗时、错误码和匿名设备标识。

## 12. MVP 验收清单

### 12.1 主流程

- [ ] 在记事本选中文字，按快捷键可唤起菜单。
- [ ] 在 Chrome 输入框选中文字，按快捷键可唤起菜单。
- [ ] 在 Word 正文选中文字，按快捷键可唤起菜单。
- [ ] 六个预设意图均可成功生成结果。
- [ ] 结果可在原文和改写版之间切换。
- [ ] 替换后目标文本正确更新。
- [ ] 替换后可撤销并恢复原文。
- [ ] 只读文本可复制结果，但不能替换。

### 12.2 异常流程

- [ ] 无选区时提示，不读取剪贴板旧内容。
- [ ] 密码框不弹出菜单。
- [ ] 网络异常时保留原文并显示重试。
- [ ] 模型超时后可取消或重试。
- [ ] 目标窗口关闭后不会向错误窗口粘贴。
- [ ] 文本超过 5,000 字时明确提示。
- [ ] 快捷键冲突时可修改。
- [ ] 多显示器和高 DPI 下菜单位置正确。

### 12.3 隐私与恢复

- [ ] 默认不保存历史。
- [ ] 用户原剪贴板在读取选区后恢复。
- [ ] 应用重启后无持久原文残留。
- [ ] 用户可在设置中查看隐私说明并清除本次会话数据。

## 13. 迭代建议

### 阶段 1：可验证原型（建议 1 周）

- 全局快捷键；
- 剪贴板读取选区；
- 浮层菜单；
- 调用一个模型完成“智能改写”；
- 结果预览与复制。

目标：验证入口、菜单位置、结果质量和替换体验。

### 阶段 2：MVP（建议 2～3 周）

- 六种改写意图；
- UI Automation + 剪贴板双通道；
- 替换与撤销；
- 设置、错误态、隐私说明；
- 记事本、Chrome、Word 兼容性验证。

### 阶段 3：增强版（后续）

- 浏览器扩展；
- 差异高亮；
- 总结、要点、列表、表格；
- 从零撰写；
- 本地历史与自定义预设；
- 富文本格式保留；
- 企业私有化部署。

## 14. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 跨应用控件兼容性不足 | 用户觉得“并非所有地方都能用” | 明确支持矩阵；提供浏览器扩展；收集兼容性反馈 |
| 模拟复制/粘贴触发安全软件 | 被误判为自动化工具 | 使用明确权限说明；优先 UI Automation；不监听键盘内容 |
| 误粘贴到错误窗口 | 破坏用户内容 | 记住目标窗口和控件；粘贴前校验焦点；失败时保留结果供复制 |
| 模型改写事实 | 用户信任下降 | 强化事实保真提示；校对模式限制改动；预览后替换 |
| 延迟过高 | 打断工作流 | 流式输出、超时、取消、缓存相同请求 |
| 快捷键冲突 | 无法唤起 | 设置页检测冲突并允许修改 |
| 用户担心隐私 | 不敢输入敏感文本 | 默认不留历史；明确数据流向；尽快提供私有化/本地模型选项 |

## 15. 待确认决策

以下问题会直接影响需求和排期，建议在产品评审前确认：

1. **目标平台**：只做 Windows 桌面端，还是同时考虑 Web / macOS？
2. **产品形态**：系统级全局工具，还是只面向网页的浏览器扩展？
3. **AI 服务**：使用哪家模型、部署在哪个区域、是否允许数据出境？
4. **内容范围**：MVP 是否只做改写，还是把总结、列表、表格一起纳入？
5. **格式要求**：MVP 是否必须保留富文本、Markdown、表格和代码块？
6. **隐私等级**：是否面向企业客户，是否需要本地模型/私有化部署？
7. **商业化**：免费额度、订阅、按次计费还是企业授权？
8. **默认快捷键**：`Ctrl+Alt+R` 是否可接受，是否需要首次启动引导设置？
9. **是否需要从零撰写**：无选区时是否要直接进入“撰写”模式？
10. **是否需要翻译**：翻译是否作为独立入口，还是归入自定义指令？
